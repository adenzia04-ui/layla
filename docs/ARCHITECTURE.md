# Noor — Architecture & Specification (v1)

> Noor (نور, "light") — a prayer companion built on Flutter + Firebase.
> Tagline: **"Stay connected with your prayers."**

**Layering rule (enforced by convention):**
`presentation` → `application` → `data` → `domain`.
`domain` is pure Dart (no Flutter, no Firebase). `core` never imports `features`.

**State management:** Riverpod (`flutter_riverpod`), hand-written providers — **no code generation**, so the project runs with `flutter pub get` alone.

## 2. User flow

```
                        ┌──────────────┐
       cold start ─────▶│    Splash    │  logo + arch animation, 1.8s
                        └──────┬───────┘
                               │ read prefs + Firebase auth state
              ┌────────────────┼────────────────────┐
     first run│                │ returning, signed in│ returning, signed out
              ▼                ▼                     ▼
      ┌──────────────┐   ┌───────────┐        ┌───────────┐
      │  Onboarding  │   │   Home    │        │   Login   │
      │  4 pages     │   └───────────┘        └─────┬─────┘
      └──────┬───────┘                              │
             │ "Get started"                        ├──▶ Sign up ──┐
             ▼                                      ├──▶ Forgot pw │
      ┌───────────┐                                 └──▶ Guest ────┤
      │   Login   │◀────────────────────────────────────────────────┘
      └─────┬─────┘                                          │
            └───────────────── success ───────────────────▶ Home
```

**Core daily loop:**

```
Prayer time arrives
   │
   ├─▶ local notification (full-screen intent on Android)
   │
   ▼
Prayer Focus session opens (30 min window)
   │
   ├── user prays ──▶ taps "I Have Prayed"        ← STEP 1
   │                        │
   │                        ▼
   │                 Photo of prayer mat REQUIRED  ← STEP 2
   │                   camera / gallery
   │                        │
   │              ┌─────────┴──────────┐
   │        upload OK              cancel / no photo
   │              │                     │
   │              ▼                     ▼
   │     status = completed      status = pending
   │     streak += (if day done) focus session stays active
   │              │                     │
   └──────────────┴─────────────────────┘
                  ▼
            Streak / calendar updates
```

**Tahajjud loop:** Tahajjud tab → sees window (last third of night) → "I am Praying Tahajjud" → consent sheet (coarse location disclosure) → presence doc created with 90-min TTL → appears on live map as a **coarse cell**, never a precise pin → "End session" or auto-expiry removes them → optionally writes a Story.

## 4. Navigation structure

`StatefulShellRoute.indexedStack` — 5 branches, each with its own Navigator so tab state survives switching.

```
Bottom navigation
┌────────┬──────────┬────────┬────────┬─────────┐
│  Home  │ Tahajjud │ Qibla  │ Tasbih │ Profile │
│   ☾    │    ✦     │   ◈    │   ⊙    │    ◉    │
└────────┴──────────┴────────┴────────┴─────────┘
    │          │
    │          ├── Live Map
    │          └── Stories ── Composer / Detail
    │
    ├── Prayer Times ── Settings
    └── Streak
```

**Full-screen routes outside the shell** (no bottom bar, no swipe-back):
`/`, `/onboarding`, `/login`, `/signup`, `/forgot-password`, `/focus/:prayer`, `/focus/:prayer/confirm`.

**Redirect rules (`app_router.dart`):**
- not signed in + protected route → `/login`
- signed in + auth route → `/home`
- **active unconfirmed prayer session → force `/focus/:prayer`** (this is the in-app half of the "lock")
- guest + `stories/new` or map presence → upgrade-account sheet

## 5. Firebase database structure

### Firestore

```
users/{uid}
  displayName        string
  email              string
  photoUrl           string?
  isAnonymous        bool
  createdAt          timestamp
  timezone           string          "Asia/Kuala_Lumpur"
  location: { lat, lng, city, country, updatedAt }   ← precise, private to owner
  settings: {
    calculationMethod  string        "muslim_world_league" | "karachi" | …
    madhab             string        "shafi" | "hanafi"
    adjustments        map<string,int>   minutes per prayer
    notifications      map<string,bool>  per prayer
    lockEnabled        bool
    tahajjudVisible    bool          ← must be true to appear on the map
  }
  stats: {
    currentStreak      int
    longestStreak      int
    totalPrayers       int
    totalTahajjud      int
    lastCompletedDate  string        "2026-08-20"
  }

users/{uid}/prayer_days/{YYYY-MM-DD}          ← doc id IS the local date
  date               string
  completedCount     int             0–5
  isComplete         bool            all 5 confirmed
  prayers: {
    fajr:    { status, scheduledAt, confirmedAt, proofPath, proofUploadedAt }
    dhuhr:   { … }
    asr:     { … }
    maghrib: { … }
    isha:    { … }
  }
  tahajjud: { prayed: bool, at: timestamp? }
  # status ∈ pending | awaiting_proof | completed | missed

users/{uid}/tasbih_sessions/{autoId}
  dhikr, target, count, completedAt

tahajjud_presence/{uid}                        ← ONE doc per user, id = uid
  displayName        string          or "A believer" when anonymous
  cellGeohash        string          5 chars ≈ 4.9 km × 4.9 km
  cellLat, cellLng   number          CENTRE of the cell + deterministic jitter
  countryCode        string
  startedAt          timestamp
  expiresAt          timestamp       startedAt + 90 min
  active             bool
  # ⚠ precise coordinates are NEVER written here

stories/{storyId}
  uid, authorName, authorPhotoUrl, isAnonymous
  body               string          40–1200 chars
  mood               string          "grateful" | "peaceful" | "hopeful" | "tested"
  createdAt          timestamp
  likeCount, reportCount   int
  status             string          published | under_review | removed

stories/{storyId}/likes/{uid}   { createdAt }

reports/{reportId}
  storyId, reporterUid, reason, note, createdAt, status
```

### Cloud Storage

```
prayer_proofs/{uid}/{YYYY-MM-DD}/{prayer}.jpg   ← private: owner read/write only
profile_photos/{uid}.jpg                        ← public read, owner write
```

### Cloud Functions

| Function | Trigger | Purpose |
|---|---|---|
| `onUserCreated` | auth.user().onCreate | seed `users/{uid}` with defaults |
| `recalculateStreak` | firestore `prayer_days/{date}` onWrite | **authoritative** streak — client value is only optimistic UI |
| `expireTahajjudPresence` | scheduled, every 5 min | delete presence where `expiresAt < now` |
| `onStoryReported` | firestore `reports/{id}` onCreate | increment counter, auto `under_review` at 3 reports |
| `onProofUploaded` | storage onFinalize | verify content type + size, stamp `proofUploadedAt` |

Rules live in `firebase/firestore.rules` and `firebase/storage.rules`.

## 7. Technical limitations — the prayer app-lock

**Short version: no Dart code can block other apps on either platform. Both platforms *can* do it from native code, by completely different routes, and neither route gives you a hard lock. Do not promise users one.**

Full analysis in [`PRAYER_LOCK_LIMITATIONS.md`](./PRAYER_LOCK_LIMITATIONS.md). Summary:

- **iOS — built and working on device; App Store distribution waits on Apple.** Apple's Screen Time API (`FamilyControls` with `.individual` authorisation + `ManagedSettings` + `DeviceActivity`) genuinely shields apps for self-imposed focus — this is how Opal, one sec and Jomo work. The full integration lives in `ios/`: the bridge in `Runner`, `NoorLockShared`, the `NoorDeviceActivityMonitor` extension and the `NoorShield` UI extension, all real Xcode targets embedded in the app. Development builds shield apps today; TestFlight and the App Store need Apple's **Family Controls (Distribution)** approval, requested for team 6RQYJNC9LM on 16 Sep 2026.
- **Android — partial, opt-in, built in v1.** A foreground service + `UsageStatsManager` polling + a `SYSTEM_ALERT_WINDOW` grant can re-surface the focus screen when the user opens another app. Costs: two special-access permissions granted manually in Settings, Play Store scrutiny of `PACKAGE_USAGE_STATS`, OEM battery killers stopping the service, and the user can always force-stop, reboot, or revoke.
- **What we ship instead:** an honest **"Prayer Focus"** — a full-screen, back-disabled, wakelock-held screen inside Noor that stays until confirmation, plus notifications, plus an *optional, clearly-disclosed* Android soft-lock behind a `PrayerLockPlatform` abstraction (`AndroidSoftLock` / `IosNoopLock`).
- **Two-step confirmation is fully implementable and is the real enforcement mechanism** — a prayer is `completed` only after the mat photo lands in Storage. Note honestly in your store listing that the photo is a personal accountability record, not verification: nothing stops a user photographing any mat. Its value is intentional friction, not proof.

## 8. Recommended Flutter packages

| Package | Why this one |
|---|---|
| `firebase_core`, `firebase_auth`, `cloud_firestore`, `firebase_storage`, `cloud_functions` | required stack |
| `flutter_riverpod` | compile-safe DI + state, no codegen needed |
| `go_router` | declarative routes + the auth/focus redirect guard |
| `adhan` | pure-Dart prayer calc; also gives `SunnahTimes.lastThirdOfTheNight` (**Tahajjud**) and `Qibla.direction` |
| `hijri` | Islamic date on the dashboard |
| `geolocator` | location + permission flow |
| `geocoding` | city name for the header |
| `flutter_compass` | magnetometer heading for Qibla |
| `permission_handler` | camera / notification / photos |
| `flutter_local_notifications` + `timezone` | exact prayer alarms, full-screen intent |
| `image_picker` | mat photo (camera + gallery) |
| `flutter_map` + `latlong2` | Tahajjud map with **no API key**; we plot coarse cells, not pins |
| `google_fonts` | Playfair Display + Inter |
| `shared_preferences` | onboarding seen, cached location, local tasbih |
| `wakelock_plus` | keep focus screen awake |
| `intl` | time/date formatting |
| `cached_network_image` | story avatars |

**Deliberately not used:** `google_maps_flutter` (API key + billing for a feature that only needs coarse cells), any codegen (`freezed`/`build_runner`) to keep the first build friction-free, `flutter_qiblah` (we compute the bearing ourselves from `adhan` so there is one source of truth).
